## 2. 항목별 근거

### 성능 — 9/10 ✅
- 콜드 페이지 로드 시 Sheets 조회 **20회 → 1회** (실측, 600행/24개월)
- 단일 비행 잠금으로 동시 요청 중복 다운로드 제거
- 기록 수정 API 3회 → 1회, 예산 조회 N명 → 1회
- 프론트: 미사용 Bootstrap JS 79KB 제거, Chart.js 렌더 차단 해제
- **남은 한계**: 시트 전체를 받아 필터링하므로 O(전체 행). 600행에선 무의미하나
  1만 행(약 10년치) 부근에서 체감됩니다. 가족 전용이면 수년간 문제 없음.

### 기능 완성도 — 8/10 ✅
- 봇: 수입/지출 기록, 카테고리, 예산·초과 경고, 차트 4종, CSV, 검색, 수정/삭제,
  가입 승인, 자동 주간·월간 리포트
- 대시보드: KPI, 차트 5종, 캘린더 히트맵, 거래 CRUD, 필터·검색, 월/연 이동
- **상용 대비 부재**: 반복 거래 자동 입력(구독료), 영수증 사진, 자산/부채 잔액,
  카드사 연동. 다만 가족 가계부 용도로는 필수가 아닙니다.

### 코드 품질·테스트 — 7/10
- 테스트 268개. 커버리지: `sheets.py` 94%, `charts.py` 93%, `dashboard/app.py` 79%,
  `budget_bot.py` 27%

- **부족**: CI에 린터·포매터·타입체크 없음(측정: `deploy.yml`에 0건).
  `index.html`이 3,200줄 단일 파일에 CSS+JS 인라인.

### 문서화 — 7/10 ✅

## 3. 개선 설계 (가족 전용 76점 목표)

우선순위는 **위험 × 비용** 순입니다. P0만 해도 66 → 73점입니다.

### P0 — 위험 제거 (필수, 반나절)

**① HTTPS 적용 → 보안 4 → 7 (+3점)**
가장 큰 단일 개선입니다. 도메인 유무에 따라 두 갈래:

- **도메인 없음 (권장): Cloudflare Tunnel** — 무료, 도메인 불필요,
  **서버 포트를 인터넷에 열 필요조차 없습니다.** 8081을 외부에 노출하지 않고
  Cloudflare가 HTTPS로 종단. 방화벽에서 8081을 닫을 수 있어 공격면이 오히려 줄어듭니다.
- **도메인 있음: Caddy** — 설정 2줄로 Let's Encrypt 자동 발급·갱신.
  nginx+certbot보다 단순합니다.

**② 쓰기 경쟁 조건 방어 → 신뢰성 6 → 7 (+1점)**
수정·삭제 직전에 그 행의 `id`가 여전히 대상과 일치하는지 재확인하고,
불일치하면 중단 후 재시도. API 1회 추가로 "엉뚱한 기록 삭제"를 막습니다.

### P1 — 안전망 (반나절)

**③ 자동 백업 → 신뢰성 7 → 8 (+1점)**
매일 새벽 Sheets 전체를 CSV로 스냅샷(서버 또는 Drive), 30일 보관.
"감당 가능" 수준이라 하셨으므로 일 1회면 충분합니다.

**④ 다운 알림 → 운영 6 → 7 (+1점)**
UptimeRobot(무료)이 5분마다 `/health`를 확인해 죽으면 알림.
또는 봇이 자기 자신을 점검해 관리자에게 텔레그램으로 통지 — 별도 서비스 없이 가능합니다.

### P2 — 품질 (하루)

**⑤ 접근성 보완 → UX 6 → 7 (+1점)**
차트 옆에 요약 텍스트(스크린리더용), 모달 포커스 트랩 + Esc 닫기,
아이콘 버튼 `aria-label` 보강.

**⑥ CI 린터 추가 → 품질 7 → 8 (+1점)**
`ruff` 한 줄 추가. 죽은 코드·미사용 임포트·잠재 버그를 자동 차단.
(이번 감사에서 `base64` 미사용 임포트를 사람이 찾아야 했던 이유)

### P3 — 선택 (여유 있을 때)

- 토큰을 HttpOnly 쿠키로 이전 (HTTPS 적용 후에 의미 있음) → 보안 +1
- 전용 계정으로 실행 (root 탈피) → 보안 +1
- `index.html` CSS/JS 분리 → 품질 +0.5
- 장애 대응 런북 → 문서 +0.5

## 4. 상용 서비스와의 거리

가족 전용을 유지한다면 **P0~P2까지가 합리적인 종착점(76점)** 입니다.
그 위(상용 89점)로 가려면 성격이 다른 투자가 필요하며, 지금 목표에는 불필요합니다:

| 상용에 필요하지만 지금은 불필요한 것 | 이유 |
|---|---|
| Google Sheets → PostgreSQL 전환 | 동시성·트랜잭션·수만 행. 가족 규모에선 Sheets의 "사람이 직접 고칠 수 있음"이 오히려 장점 |
| 사용자별 계정·권한 분리 | 공용 비밀번호로 충분한 신뢰 관계 |
| 감사 로그(누가 무엇을 언제) | "감당 가능" 답변 기준 과투자 |
| 결제·구독, 약관·개인정보 처리방침 | 타인의 금융 데이터를 다루면 법적 요건 발생 |
| 다국어, 24/7 대응 체계 | 대상 사용자 특성상 불필요 |

## 5. 결론

- **지금이 최선인가?** 성능·기능은 예. 보안은 아닙니다.
- **가장 큰 한 가지**: 평문 HTTP. 다른 모든 항목을 합친 것보다 개선 효과가 큽니다.
- **P0만 적용해도** 66 → 73점으로, 가족 전용 목표선(76)에 근접합니다.
- **P0~P2 완료 시 76점** — 가족용 개인 프로젝트로서 사실상 상한입니다.
